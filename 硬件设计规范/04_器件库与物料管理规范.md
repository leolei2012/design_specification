## 1. 目标、现状与适用边界

保证采购型号、数据手册、符号、封装、实物及项目BOM能够相互追溯，降低引脚映射、封装和替代料错误。

本规范依据物料库提交 `9ccb48e1d46a435447ecd80c44dd8da5b865233d` 编写。该库面向KiCad 10.x，已有目录、库表模板、字段约定及版本规则；`parts.csv` 只有表头，`MyParts.kicad_sym` 为空库，尚无实际封装文件。本文描述的是拟采用的管理流程，不表示已有器件通过验证。

- **必须**：入库或项目发布前满足，偏离须有原因、风险、验证证据和批准记录。
- **应**：默认执行，不采用时说明理由。
- **建议**：按规模选用。

KiCad官方手册负责软件行为说明，KLC用于参考库设计约定；本文的物料编码、验证状态和审核流程为团队约定。具体引脚、焊盘和工作条件以准确订货型号的厂家资料为依据。

## 2. 库对象与物料对象

| 对象 | 标识示例 | 含义及约束 |
|---|---|---|
| 物料 | `Part_ID`，例如 `P000001` | 一个受控采购定义；编码永久唯一，停用后不复用 |
| 采购型号 | `Manufacturer` + `MPN` | 厂家及完整订货号，不能只记录系列名或商城简称 |
| 符号 | `MyParts:<Symbol_Name>` | 电气表达，可被多个合适物料复用，不必与物料编码相同 |
| 封装 | `MyFootprints:<Footprint_Name>` | 焊盘与装配几何，多个物料可共用，但逐个核实适用性 |
| 三维模型 | 相对路径及来源版本 | 用于装配辅助，不能替代焊盘和器件尺寸核对 |
| 库基线 | Git完整提交、发布标签 | 一组库文件与台账的确定版本 |

初期建议使用无类别含义的顺序编码 `P000001`、`P000002`，器件类别和参数写入属性。已有公司编码时沿用，不另建冲突编号；多人同时申请编码时由维护者统一分配，合并前检查重复。

| 编号 | 等级 | 规则及检查依据 |
|---|---|---|
| MAT-01 | 必须 | 同一物料编码的厂家、订货号、封装及受控规格含义稳定；改变身份的采购型号建立新物料编码。 |
| MAT-02 | 必须 | 同名封装、相同顶标或同系列型号不能作为可替代依据；完整订货号需覆盖电气、温度、封装及包装后缀。 |
| MAT-03 | 应 | 初期一个完整订货号对应一条物料记录。若卷带、托盘等包装不同，分别记录订货号及编码，并注明电气等效关系；不将多个订货号塞入一个MPN单元格。 |
| MAT-04 | 必须 | 供应商及商城编号属于采购来源，不能替代厂家身份；价格、库存、订单和采购批次另行管理。 |
| MAT-05 | 必须 | 一个物料可用于多个项目，不因项目不同复制编码；同一符号可对应多个物料，不强制一物料一个符号。 |

通用电阻、电容等可使用通用符号，在项目实例中填写准确物料编码及采购属性；专用IC可建立带默认采购属性的符号。通用符号不能预填一个具体MPN后被无检查地用于全部阻值、耐压或精度。

## 3. 沿用现有目录与注册方式

```text
kicad_library/
├── symbols/MyParts.kicad_sym
├── footprints/MyFootprints.pretty/<Footprint_Name>.kicad_mod
├── datasheets/                      # 有权保存的厂家资料
├── 3dmodels/                        # STEP等模型
├── docs/
│   ├── OFFICIAL_DOCS.md             # 已有官方资料索引
│   └── reviews/<Part_ID>/           # 建议新增：核对、验证与变更证据
├── templates/
│   ├── sym-lib-table
│   └── fp-lib-table
├── parts.csv
└── CHANGELOG.md
```

本规范不要求立即重命名 `MyParts` 和 `MyFootprints`。库昵称是符号及封装引用的一部分，后续拆分类别库或重命名时按不兼容变更处理，验证受影响项目。

项目内库路径沿用现有模板：

```text
${KIPRJMOD}/kicad_library/symbols/MyParts.kicad_sym
${KIPRJMOD}/kicad_library/footprints/MyFootprints.pretty
```

`${KIPRJMOD}` 指向KiCad工程目录。库必须按该布局放置，或在库管理器中明确调整路径；不能将模板原样用于任意位置。已有工程库表应合并条目，禁止直接覆盖。数据手册、3D模型及共享依赖同样验证路径，不依赖个人绝对路径。

## 4. 台账与符号属性的分工

### 4.1 沿用 `parts.csv` 的20个字段

不为执行本规范立即更改现有CSV表头。以下为字段填写要求，状态有条件的字段允许暂空，但须在审核时说明。

| 字段 | 填写要求 |
|---|---|
| `Part_ID` | 创建时分配，非空且唯一 |
| `Manufacturer`、`MPN` | `reviewed`前填写厂家与完整订货号 |
| `Description` | 类别、关键规格和准确封装；不能只有笼统名称 |
| `Symbol`、`Footprint` | 电气器件写完整库标识；纯机械件等不适用项在Notes说明 |
| `Datasheet_URL` | 厂家原始资料入口；无法获取时记录原因及其他可靠依据 |
| `Datasheet_File` | 离线副本的库根相对路径；无副本时可空 |
| `Datasheet_Revision` | 文档编号、修订号或可定位版本；无修订号时记录日期与文件校验信息 |
| `Source_URL`、`Retrieved_Date` | 库对象或资料来源、获取日期；多个来源在核对记录逐项展开 |
| `Supplier`、`Supplier_PN`、`Purchase_URL` | 已核实的采购来源；未选定可空，不影响电气资料审核结论 |
| `Model_File` | 模型相对路径；无模型可空，不以模型缺失直接判定电气器件不合格 |
| `Verification` | 采用第7章的既有状态值 |
| `Verified_Date`、`Verified_Project` | 记录当前验证依据的日期、项目/报告标识；draft无验证时可空 |
| `Library_Revision` | 本物料映射及定义的修订标识，例如 `r1`，不是整个库的版本标签 |
| `Notes` | 限制、来源补充、例外及证据路径；禁止放密码、令牌等敏感信息 |

物料无电气符号或无贴装封装时，例如散热器、螺钉、线缆，应明确BOM纳入方式和机械定义，不为填满字段创建虚假符号或封装。

### 4.2 数据主来源及一致性

- `parts.csv` 是具体物料身份、默认映射和验证状态的主台账。
- 符号/封装源文件是引脚、图形、焊盘和实际几何的主来源；台账不能覆盖其真实内容。
- 项目实例维护实际选用的 `Part_ID`、`Manufacturer`、`MPN`、`Value`、`Footprint` 及装配状态；BOM导出时与台账交叉检查。
- 专用符号沿用现有 `Manufacturer`、`MPN`、`Supplier`、`Supplier_PN`、`Purchase_URL`、`Verification`、`Library_Revision` 字段，并建议增加 `Part_ID`；通用符号的采购身份在项目实例中填写。
- `Reference`、`Value`、`Footprint`、`Datasheet`、`Description` 按KiCad字段含义保留。器件排除BOM、排除贴装及DNP设置按实际用途检查，不能只凭备注文字判断。

CSV与符号属性目前没有自动同步机制。修改受控身份或映射时，同时检查两处及受影响项目；BOM必须以实际工程导出，不能把整个 `parts.csv` 当作项目BOM。

### 4.3 后续扩展建议

器件数量增加后，可评审新增 `Lifecycle`、`Review_Record` 字段，分别记录采购生命周期及验证证据位置。新增字段前更新README、导出工具及字段说明，不宣称现有库已经支持自动同步或审批。

多个供货渠道可另建以 `Part_ID` 关联的采购台账；替代料可另建关系表，避免不断增加 `Supplier2`、`MPN2` 等列。初期可将相关记录放入 `docs/reviews/<Part_ID>/`。

## 5. 新器件入库和复核

1. **查重和选源**：按厂家及完整MPN查台账，再检查官方库是否存在准确适用的对象，记录来源及许可证。
2. **建立草稿**：分配Part_ID，状态设 `draft`，填写资料版本和拟采用的符号、封装。
3. **符号复核**：逐引脚检查编号、名称、电气类型、方向、隐藏电源脚、多单元、NC/保留脚及裸露焊盘，不以ERC无错误替代手工映射检查。
4. **封装复核**：依据厂家精确封装图及推荐焊盘核对编号、脚距、焊盘、孔径、阻焊、钢网、Pin 1、极性、外形和courtyard。注明顶视/底视，区分器件尺寸与焊盘尺寸。
5. **三方映射复核**：建立“厂家实物引脚—符号引脚—封装焊盘”对照，尤其检查连接器观察方向、二极管极性、MOSFET脚序及裸露焊盘。
6. **工程验证**：在测试工程放置并注释器件，更新PCB，运行适用ERC/DRC，核对BOM、封装引用及模型比例/方向，记录工具版本和未通过项。
7. **资料审核**：提交核对证据，关键器件由另一人复核；个人维护时至少分两次按清单复核并标明“自审”，不冒充独立审核。满足条件后标记 `reviewed`。
8. **实物验证**：按具体样板记录焊接、方向、机械配合及相关电气功能结果，确认被验证对象及范围后标记 `prototype_verified`。
9. **提交及固定基线**：库文件、台账、核对记录和CHANGELOG一并提交，项目固定明确的库提交；需要发布时按第9章管理。

对多个MPN共用的封装，复用封装实物证据只能证明相应几何的已测范围，不代表所有MPN的电气性能及可替代性均已验证。修改共享封装前列出全部引用物料。

## 6. 参数与命名要求

| 类别 | 至少核对的采购规格 |
|---|---|
| 电阻 | 阻值、容差、额定功率、工作电压、温度系数及封装；分流电阻另查端子与采样方式 |
| 电容 | 容值、耐压、容差、介质/极性、有效容量及温度；根据用途核对ESR、纹波等 |
| 电感/磁珠 | 感量或指定频率阻抗、额定/饱和电流、直流电阻、尺寸及温度条件 |
| 二极管/MOSFET | 极性、引脚、耐压、电流、损耗及驱动条件，不能只按封装和名义额定值替换 |
| IC | 完整型号、封装代码、引脚表、供电、温度等级、关键性能和勘误 |
| 连接器 | 节距、排数、脚序、观察面、插合型号、键位、额定值及机械尺寸 |
| 晶体/振荡器 | 类型、频率、负载、精度、驱动/供电、脚序及封装 |

参数依据工作条件核对，不将一组固定降额百分比作为所有器件的通用判据。

符号名建议体现准确型号及必要的封装区别；封装名体现类型、引脚数、尺寸与脚距，尺寸标明单位，并参考KLC。名称不用空格，不依靠大小写区分对象。通用名称不暗示未经验证的多厂家兼容性。

## 7. 验证状态与采购生命周期

保持现有四个 `Verification` 枚举，避免破坏后续工具兼容性：

| 状态 | 进入条件 | 项目使用要求 |
|---|---|---|
| `draft` | 新建、证据不足，或影响正确性的变更后待复核 | 可用于探索，不直接作为生产发布的合格依据 |
| `reviewed` | 准确资料、映射、库对象及适用工程检查已完成，有可追溯记录 | 可用于受控打样；量产前仍按项目完成实物及产品验证 |
| `prototype_verified` | 在明确库修订、项目与样机上完成相关实物验证，有范围和结果 | 不代表适用于所有电压、温度、工艺及项目 |
| `deprecated` | 不建议新设计使用，记录原因、日期及推荐后续处理 | 旧项目是否继续使用需单独评估；不删除历史证据 |

此枚举中的 `deprecated` 是使用限制，不能表达器件所有历史验证事实。停用时在核对记录保留先前状态、修订和证据；解除停用需重新审核，不能自动恢复。

厂家生命周期与库验证状态分开管理。器件可能已实物验证但厂家宣布停产，也可能正常供货但尚未核对。初期在Notes或核对记录中登记 `active / NRND / EOL / unknown`、信息来源和查询日期，不能仅凭商城“有库存”认定厂家仍在生产。

## 8. 替代料与采购一致性

| 编号 | 等级 | 规则及检查依据 |
|---|---|---|
| ALT-01 | 必须 | 替代料建立自己的Part_ID及完整MPN，记录目标物料、适用项目/硬件版本和装配变体；不得直接覆盖原物料的MPN。 |
| ALT-02 | 必须 | 分别核对封装/脚序、电气性能、温度、可靠性、时序及固件影响，记录差异和验证证据；Pin-to-Pin不等于无需验证。 |
| ALT-03 | 必须 | 明确“可直接替换”“需改BOM/装配选项”“需改硬件/固件”的条件及批准人；替代关系不默认双向或可传递。 |
| ALT-04 | 必须 | 采购按已批准BOM和替代清单下单，缺货时发起替代审核，不由采购链接相似或供应商推荐直接放行。 |
| ALT-05 | 应 | 来料及装配记录能够关联厂家型号、供货来源、批次和装配版本；发现错料、假料或异常时隔离并追溯。 |

推荐的替代关系记录字段：原Part_ID、替代Part_ID、适用项目/版本、替代方向、差异、必要修改、验证报告、批准人、日期及状态。供应商变化但厂家MPN不变时，评估渠道和质量风险，不自动创建一个新的电气等效关系。

## 9. 变更、库发布与项目锁定

| 变更类型 | 处理原则 |
|---|---|
| 资料链接或文字修正 | 检查是否改变设计含义；无影响时保留状态并记录原因 |
| 引脚编号、电气类型、焊盘、孔径、极性或默认映射变化 | 提升Library_Revision，列出受影响物料/项目，重新执行相关复核；无法证明有效性时退回draft |
| 具体采购身份改变 | 建立新Part_ID，明确替代或停用关系 |
| 删除、重命名符号/封装/库昵称 | 优先停用保留；确需删除或重命名时提供迁移说明，按不兼容变更管理 |

沿用库README的版本策略：不兼容变化升主版本，兼容新增升次版本，不改变连接或焊盘几何的修正升补丁版本。影响电气连接或焊盘的修正不得仅因名为“修复”就默认按补丁处理。`Library_Revision`、库发布版本、项目硬件版本分别记录，不混为同一字段。

项目通过子模块、受控快照或其他可恢复方式固定库完整提交，并记录KiCad版本及外部官方库版本。日常库更新不自动成为项目发布基线。更新已放置符号/PCB封装时：

1. 保存项目变更前基线并列出目标库修订。
2. 在KiCad中显式更新，检查已有字段是否被覆盖、符号引脚是否改变及封装是否移位。
3. 复核关键网络、焊盘、板框空间、BOM及装配选项，运行相关ERC/DRC与输出检查。
4. 记录结论并按项目变更流程决定是否更新硬件修订和发布编号。

已发布项目不得静默拉取共享库最新版本；必要的依赖快照包含实际模型和资料，不只保存失效路径或Git/LFS指针。

## 10. 核对记录与入库检查表

建议每个物料在 `docs/reviews/<Part_ID>/` 保存核对记录，至少包含：

```text
物料编码 / 厂家 / 完整MPN：
符号 / 封装 / Library_Revision：
资料版本、来源、来源库提交及许可：
引脚与焊盘对照、几何核对依据：
KiCad版本、测试工程及测试基线：
ERC/DRC结果、例外和限制：
实物项目、板卡版本、样机编号及验证范围：
作者、复核者（独立审核或自审）、日期：
结论、Verification状态及待办事项：
```

测试工程和大文件可放在受控外部位置，但记录须能准确定位并确认可获取。无需为每个物料复制共享封装的完整证据，可引用其明确版本。

| 序号 | 检查项 | 结果/证据 |
|---|---|---|
| 01 | Part_ID唯一，厂家和完整MPN准确 | 待检查 |
| 02 | 关键采购规格、准确封装和厂家资料版本明确 | 待检查 |
| 03 | 符号引脚编号、电气类型及多单元/隐藏脚已核对 | 待检查 |
| 04 | 封装焊盘、孔径、阻焊/钢网和方向有依据 | 待检查 |
| 05 | 实物引脚、符号引脚和封装焊盘对应正确 | 待检查 |
| 06 | 模型和资料路径可恢复，来源与许可已记录 | 待检查 |

## 11. 在当前库中的实施顺序

1. **先试入库**：选择常用电阻、电容、一个IC和一个连接器，按现有表头完成记录，验证通用符号与专用符号两种用法。不预先虚构器件或验证结论。
2. **补齐证据入口**：在物料库评审后新增核对记录模板及 `docs/reviews/`，将本规范链接到库README，补充Part_ID字段约定。
3. **建立轻量检查**：器件实际入库后再实现CSV必填/唯一性、库标识存在、路径和状态取值检查；自动检查不得自动授予reviewed或prototype_verified状态。
4. **项目试用**：固定库提交，完成一次工程打开、BOM导出、打样和实物验证，依据结果调整规范。
5. **按需要扩展**：器件与渠道增多后再拆分类别库、替代关系及供应商台账；不先引入无人维护的复杂系统。

上述是后续物料库的建议改动。本次规范编写未修改物料库表头、库对象或验证状态，也未运行KiCad器件或实物验证。
